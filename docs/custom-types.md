# Custom entity types

Upstream Graphiti takes custom entity types as `dict[str, type[BaseModel]]`: a Pydantic model per type, whose docstring
describes the type and whose fields are the attributes the LLM extracts. graphiti-net takes an
`IReadOnlyDictionary<string, Type>`, where each `Type` is a class or record.

```csharp
[Description("A human person. GOOD: \"Alice Smith\". BAD: \"someone\".")]
public sealed record Person
{
    [Description("The person's first name")]
    public string? FirstName { get; init; }

    [Description("Phone numbers, comma-separated")]
    [MaxLength(100)]
    public string? Phones { get; init; }
}

var entityTypes = new Dictionary<string, Type> { ["Person"] = typeof(Person) };
```

## How a type maps from Pydantic

| Upstream (Pydantic) | graphiti-net |
| --- | --- |
| Type name (the dict key) | The dictionary key; it becomes a node label, so it must be a safe identifier. |
| Class docstring | `[Description]` on the class. No attribute means no description (`None` in the prompt). |
| Field name | The property's JSON name: snake_case of the property name (`FirstName` → `first_name`), or `[JsonPropertyName]`. |
| `Field(description=...)` | `[Description]` on the property. |
| `Field(max_length=n)` | `[MaxLength(n)]` or `[StringLength(n)]` (used by the attribute length cap). |
| Required field (no default) | The `required` modifier, `[JsonRequired]`, or a non-nullable positional record parameter without a default. |
| `str | None = None` | A nullable property without `required`. |

The JSON schema sent to the LLM is generated by `ResponseSchema` with the same snake_case options as every other
response model, and matches what Pydantic would generate for the equivalent model.

## What happens at ingestion

- **Extraction** (`NodeOperations.ExtractNodesAsync`): the prompt lists `Entity` as type 0 and each custom type in
  dictionary order with its description. Excluded types are removed and the rest renumbered from 0. A node gets the
  labels `Entity` and its type name.
- **Attributes** (`NodeOperations.ExtractAttributesOnlyFromNodesAsync`): for a node whose labels include a custom type
  with at least one property, `extract_nodes.extract_attributes` runs with the type as the response model. The
  answer is capped (`AttributeUtils`: string values over 250 code points, or the field's `MaxLength`, or the
  `GRAPHITI_ATTRIBUTE_MAX_LENGTH` environment variable, are dropped unless the field is required), overlaid on the
  node's prior attributes (an explicit `null` keeps a non-null prior value), and checked by deserialising into the
  type; the instance itself is discarded, as upstream.
- **Storage**: attributes land in `EntityNode.Attributes` as JSON-compatible values: `string`, `long`, `double`,
  `bool`, `null`, `Dictionary<string, object?>` and `List<object?>`. Keys are the JSON (snake_case) names. Keys the
  LLM returns that the type does not declare are kept, as upstream.
- **Summaries**: with type descriptions enabled, the summary prompt gets the first paragraph (at most three
  sentences) of each type's description.

## Validation

- `EntityTypesUtils.ValidateEntityTypes` rejects a type with an attribute named like an `EntityNode` field: `uuid`,
  `name`, `group_id`, `labels`, `created_at`, `name_embedding`, `summary` or `attributes`
  (`EntityTypeValidationException`).
- `EntityTypesUtils.ValidateExcludedEntityTypes` rejects excluded names that are neither `Entity` nor a custom type
  (`ArgumentException`, upstream's `ValueError`, with the same message).

## Differences from Pydantic

- Validation of the merged attributes uses System.Text.Json, which is stricter than Pydantic's lax mode: it does not
  coerce `"30"` into an `int` property. Prefer `string?` properties for values the LLM may format loosely.
- Pydantic-only features (validators, `Literal`, `json_schema_extra`, constraints other than `max_length`) have no
  equivalent.
